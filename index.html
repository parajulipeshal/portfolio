A two-player Battleship game for a software engineering class. One player creates a game in the lobby, another joins, both place ships, then they take turns firing.

Decisions I'd make again

  • The game is a state machine. A GameState enum moves from WaitingForPlayers to PlacingShips to InProgress to GameOver. Moves that don't fit the current state get rejected instead of half-working.
  • Storage behind an interface. IStorage has a JSON FileDataStore and a MemoryDataStore. The tests use the memory one, so they never touch the disk.
  • Ships come from a factory. ShipFactory.CreateShip(length) picks the class, so a new ship type is one new class plus one line.
  • The lobby raises an event. LobbyChanged lets open pages update when someone creates or joins a game.

Tested

19 xUnit tests cover placing ships (valid and invalid), hits, misses, turn switching, out-of-bounds attacks, player lookups and both data stores.

Still broken

Feedback I got: after the last ship is placed, the board needs one extra click before the game starts. I haven't fixed it yet.

A Powerball-style lottery library from my operating systems class: open a sales period, sell tickets, draw numbers, find the winners. Then we stress it with lots of stores selling at the same moment.

What I worked through

  • One shared list, one lock. Every read and write to the sold tickets goes through the same lock object. Without it, 100 tasks appending at once lose tickets or crash.
  • A rush-hour demo. 100 store tasks each sell 1,000–2,000 tickets, awaited together with Task.WhenAll. Then the count is checked against what was actually sold.
  • Scoring in parallel. After the drawing, the tickets are split into three slices and scored on three tasks, then merged into one result.
  • Time is a parameter. Methods take a DateTime instead of calling DateTime.Now, so tests can pretend it's any day of the sales week.

Tested

An NUnit project covers tickets, the prize calculator and the agency's sales rules.

Case study · C# threads · Works

Making five professors deadlock, then fixing it

Dining philosophers, with professors. Five threads sit around a table with five forks between them, and each fork is a lock. To eat, a professor needs the fork on the left and the fork on the right.

The program has three versions behind one flag:

  1. Version 1 deadlocks on purpose. Everyone grabs left, then right. If they all grab left at once, every fork is taken and everyone waits forever. The demo gives up after five seconds.
  2. Version 2 fixes it with one change. Professor 4 picks up the right fork first. That breaks the circle of waiting, so everyone finishes five bites.
  3. Version 3 shows its work. It prints who holds which fork after every pick-up and put-down.
// Professor 4 changes the order
if (version != 1 && id == 4)
{
    first  = right;
    second = left;
}

The Nepal Courtyard · About

नमस्ते, I'm Peshal.

I grew up in Nepal and studied computer science for my +2 at Capital College and Research Center in Kathmandu. In 2025 I moved to Ephraim, Utah, to study Computer Software Engineering in the Honors Program at Snow College. I came through the EducationUSA Opportunity Funds program.

Back home I kept starting things. In 2023 I founded Everest TechSo Network, a student-led group teaching computer science and AI, and we organized Nepal's first code debugging competition. In high school I co-founded Mold Skill, a study site with notes and exam prep for friends and juniors. I still mentor students at Think Big.

At Snow College I led the Computer Science Club for a year. Right now I'm a Resident Assistant, a Physics grader, and the Honors Program assistant. That's a lot of name tags.

What I care about

  • Software someone actually uses. A small tool that helps one person beats a big demo nobody opens.
  • Accessibility. If it doesn't work with a keyboard or a screen reader, it doesn't work. This site has to pass that too.
  • Knowing what's underneath. Linux, threads, networks: the parts that explain why the app above them behaves the way it does.
  • Teaching what I just learned. Most of my clubs and side projects started as "let me show you how I did this."
